# 智膳校园外卖点餐系统------前端需求与页面说明

**项目名称：** 智膳校园外卖点餐系统\
**文档版本：** v1.0

## 1. 文档说明

本文档整理系统前端需要实现的页面、交互和接口调用要求，作为 Vue
页面开发、前后端联调和界面验收的依据。

系统采用校园单商家点餐模式，前端分为用户端和管理端。用户端负责浏览菜品、管理购物车、提交订单和查看订单；管理端负责维护分类与菜品、处理订单和查看经营数据。

## 2. 技术方案

  技术           用途
  -------------- --------------------------------------
  Vue 3          构建前端单页应用
  Element Plus   提供表单、按钮、表格、弹窗等界面组件
  Pinia          管理登录状态及需要跨页面共享的数据
  Axios          调用后端 HTTP 接口

前端与后端分开运行，通过 HTTP 接口交换 JSON 数据。前端不直接连接
MySQL，也不负责最终的价格、库存和权限判断；这些业务规则以服务端校验结果为准。

## 3. 页面与功能

### 3.1 用户端

  页面       功能                                       优先级
  ---------- ------------------------------------------ --------
  注册页     输入用户名、密码和手机号，提交注册         P0
  登录页     输入账号和密码，登录成功后保存 Token       P0
  点餐首页   展示菜品分类和已上架菜品                   P0
  菜品搜索   按菜品名称搜索                             P0
  购物车     查看菜品、修改数量、删除项目和清空购物车   P0
  提交订单   选择收货地址、确认菜品和订单金额并提交     P0
  模拟支付   用户确认后调用模拟支付流程                 P0
  订单列表   分页展示当前用户的订单                     P0
  订单详情   展示订单金额、状态、收货信息和菜品明细     P0
  收货地址   新增、修改和删除自己的收货地址             P1

用户端只展示已上架菜品。菜品能否购买，最终以创建订单接口的校验结果为准。如果菜品已下架或库存不足，页面应展示后端返回的原因，并引导用户调整购物车。

### 3.2 管理端

  页面         功能                                           优先级
  ------------ ---------------------------------------------- --------
  管理员登录   管理员账号登录                                 P0
  分类管理     新增、修改、删除分类，调整分类顺序             P0
  菜品管理     维护名称、价格、分类、辣度、库存和上下架状态   P0
  订单管理     查看全部订单，并按规定流程更新订单状态         P0
  经营统计     展示当日订单数量和营业额                       P1
  图片管理     上传菜品图片并关联图片地址                     P1
  店铺状态     查看并切换营业或休息状态                       P1

管理端页面可以根据当前登录角色控制菜单和按钮的显示，但这只用于界面交互。真正的权限控制由后端完成，前端不能把隐藏按钮当作安全措施。

## 4. 前端交互要求

### 4.1 登录状态

-   登录成功后保存后端返回的 Token。
-   调用需要登录的接口时，在请求头中携带 Token。
-   退出登录时清除本地登录凭证，并返回登录页。
-   如果接口返回未认证错误，应清理失效凭证，并提示用户重新登录。
-   用户端和管理端应根据登录角色展示对应入口；无权访问的请求仍由后端拒绝。

### 4.2 菜品浏览与购物车

-   首页按分类展示已上架菜品。
-   搜索框支持按菜品名称查询。
-   用户可以将菜品加入购物车，并修改购买数量。
-   购物车应显示菜品名称、单价、数量和小计。
-   删除项目和清空购物车前，应提供清晰的操作反馈。
-   菜品价格和库存展示以接口返回的数据为准。

### 4.3 提交订单与模拟支付

提交订单前，页面应展示本次购买的菜品、数量、收货信息和订单金额。金额仅用于展示，最终金额由后端重新计算。

订单创建成功后，页面进入订单确认或模拟支付环节。用户确认模拟支付后，调用对应接口；成功后刷新订单状态并展示"制作中"。

如果创建订单失败，例如菜品下架或库存不足，应保留用户当前页面状态，并明确展示失败原因，方便用户修改购物车后再次提交。

### 4.4 订单展示

订单列表应支持分页，并展示订单编号、创建时间、金额和当前状态。订单详情展示菜品明细及下单时的收货信息。

页面应根据订单状态控制可用操作：

-   待支付：允许用户取消订单，并可进入模拟支付。
-   制作中：按系统规则提供取消入口。
-   配送中、已完成：不显示直接取消入口。
-   已取消：展示取消状态，不再提供支付或状态推进操作。

前端按钮状态只是交互提示，操作是否允许仍由后端校验。

### 4.5 管理端操作

-   分类和菜品列表应提供必要的新增、编辑、删除或上下架入口。
-   订单管理页面应清楚展示订单状态，并只提供当前状态允许执行的操作。
-   经营统计页面展示后端返回的当日订单数量和营业额。
-   图片上传成功后，将后端返回的图片地址用于菜品展示。
-   店铺状态页面展示当前营业或休息状态，并允许管理员切换。

## 5. 页面与接口对应关系

所有后端接口统一使用 `/api` 前缀。前端通过 Axios
统一封装请求，具体请求字段和响应格式以接口文档为准。

  页面或功能   接口路径                              用途
  ------------ ------------------------------------- --------------------------------
  注册页       `POST /api/register`                  提交注册信息
  登录页       `POST /api/login`                     登录并取得 Token
  点餐首页     `GET /api/categories`                 获取分类
  点餐首页     `GET /api/dishes`                     获取菜品，支持分类和关键词过滤
  购物车       `GET /api/cart`                       查询购物车
  购物车       `POST /api/cart`                      添加购物车项目
  购物车       `PUT /api/cart`                       修改购物车项目
  购物车       `DELETE /api/cart`                    删除或清空购物车项目
  订单页       `POST /api/orders`                    创建订单
  订单页       `GET /api/orders`                     分页查询当前用户订单
  订单详情     `GET /api/orders/{id}`                查询订单详情
  订单详情     `PUT /api/orders/{id}/cancel`         取消订单
  分类管理     `/api/admin/category`                 分类增删改查
  菜品管理     `/api/admin/dish`                     菜品增删改查
  订单管理     `PUT /api/admin/orders/{id}/status`   更新订单状态
  经营统计     `GET /api/admin/stats`                获取统计数据
  店铺状态     `GET /api/shop/status`                查询营业状态
  店铺状态     `PUT /api/admin/shop/status`          修改营业状态

购物车接口的具体 HTTP
方法和参数形式，应与后端最终接口定义保持一致。模拟支付接口在现有接口清单中尚未单独列出，前后端联调前需要补充并确认其路径、请求参数和响应格式。

## 6. 界面状态与异常提示

前端应处理常见的页面状态，避免接口请求过程中出现空白页面或无反馈操作。

  场景                 页面处理
  -------------------- --------------------------------------------
  数据加载中           显示加载状态
  列表无数据           显示空状态提示
  请求失败             展示简洁明确的错误信息，并允许适当重试
  登录过期             清理失效 Token，提示重新登录
  菜品下架或库存不足   显示后端返回的原因，允许用户调整购物车
  提交订单成功         展示订单创建结果，并引导进入订单或支付页面
  操作成功             显示成功提示，并刷新受影响的数据

接口采用统一 JSON 响应结构时，前端应根据 `code` 判断业务结果，并使用
`message` 展示必要提示。不要只根据 HTTP 请求是否成功就认定业务操作成功。

## 7. 非功能要求

-   列表页面应使用分页，每页最多展示 20 条记录。
-   以 Chrome 稳定版作为主要测试浏览器。
-   管理端和用户端的页面入口应区分清楚。
-   表单应进行基础的必填项和格式校验；后端仍需再次校验。
-   订单、购物车等关键操作应提供明确的成功或失败反馈。
-   页面布局应保持清晰，优先保证主要点餐流程易于操作。

## 8. 前端验收与测试

  测试场景               预期结果
  ---------------------- --------------------------------------------
  用户注册并登录         能正常完成注册和登录
  浏览菜品               能按分类查看已上架菜品
  搜索菜品               能按名称筛选结果
  添加和修改购物车       页面数量及金额展示随操作更新
  空购物车提交           页面展示后端返回的失败提示
  菜品下架后结算         页面提示菜品不可购买
  库存不足时结算         页面提示缺货原因，不误报下单成功
  模拟支付成功           订单状态更新为制作中
  查看订单               只能看到当前账号的订单
  取消已完成订单         页面提示操作不允许
  普通用户打开管理入口   页面不展示管理员功能；后端仍应拒绝越权请求
  接口异常               页面显示错误提示，不出现整页白屏

## 9. 开发阶段与交付内容

### 第一阶段：核心页面（与后端核心功能同步）

完成注册登录、菜品浏览、搜索、购物车、提交订单、模拟支付和订单查询页面。先保证流程完整，再处理视觉细节。

### 第二阶段：功能补充与体验优化

完成收货地址、管理端分类和菜品维护、订单管理、经营统计、图片上传及店铺状态页面；统一加载、空状态和异常提示。

### 第三阶段：联调与测试

配合后端完成接口联调，检查登录状态、角色入口、订单状态和异常处理，修复问题并整理页面使用说明。

## 10. 前端交付成果

1.  可运行的 Vue 3 前端项目，包含用户端和管理端页面。
2.  Axios 请求封装及登录状态管理。
3.  页面交互和接口联调结果。
4.  前端测试记录及系统使用说明。
